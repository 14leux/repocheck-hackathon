# Build plan — Everyday track, live Vercel demo

**Track:** Everyday (switched 2026-09-20, per `council-transcript-20260920T001404.md`).
**Framing:** an everyday developer tool that tells you honestly when it doesn't
know, instead of guessing wrong quietly. The Fable-vs-comparator finding is a
disclosed strength (rigor), not a liability to manage around.
**Non-negotiable rule carried over unchanged:** never execute scanned code,
never place the API key in client code, `ANALYSIS_FAILED` never displays as
"no findings."

Time is the scarce resource. Every milestone below has a budget and a cut
line — what to drop first if running over. **M6 (freeze + rehearse) is never
cut.** If time runs short, cut UI polish (M4/M5) before correctness (M1/M2).

## M3 — Cache + rate limit (budget: 10 min) — DONE (`aba3242`)

- [x] Committed JSON snapshots (`demo_data/*.json`), generated by
      `hackathon/generate_demo_cache.py`, each with `verified_live_at`.
      Went further than "rate limit": `run_case_live()` (the only function
      that calls Anthropic) isn't reachable from the public handler at all

      it, since a cached-but-real result already satisfies "live verified."
- [x] Real fixture bug found and fixed along the way:
      `reviewer-note-sanity-b`'s quoted paragraph was markdown-wrapped
      across 6 lines (each starting `> `), so any model's natural
      re-quoting dropped the mid-quote markers and failed citation
      validation deterministically — confirmed identical on Fable (3/3)
      and the comparator (2/2), so not a Fable issue. Reflowed to one
      line, `snapshot_digest` recomputed, regenerated cache: clean
      `NO_EXCESS_FOUND_IN_SCOPE` on both models now.
- [x] Verified live on the redeployed public endpoint: `cached: true`,
      timestamp present, no live call fires per request.
- **Stretch, not core path:** a rate-limited "run it again, live" button
  (e.g. 1 fresh call per case per 10 min). Build this only if M1–M2 finished
  under budget. The cached-with-timestamp result is sufficient to be
  honestly "live-verified" without it.

### Submission field drafts (Everyday track)

- **Project name:** Dr. RepoCheck
- **One sentence:** Before a developer installs a Claude Code skill, Dr.
  RepoCheck shows whether it would do more than they authorized — and cites
  the exact lines that prove it.
- **Track:** Everyday
- **Live link:** https://repocheck-hackathon.vercel.app
- **What's live vs. mocked:** Live — real Anthropic API calls (cached and
  timestamped, not re-run per visitor, so the page loads instantly and
  costs stay bounded), real bundling/citation validation, real static repo
  scan. Mocked/synthetic — the three demo skills are inert fixtures we
  wrote (fictional credentials, `.test`/`.invalid` destinations, nothing
  executed or installed); the site itself caches results rather than
  calling the model on every page load.
- **Why it matters / what's missing without it:** the three damage stories
  and three absence stories drafted earlier this session, already on the
  live site's hero and disclosure sections verbatim.
- **AI tools used:** Claude Code (this session) wrote and refactored the
  Python pipeline, the Vercel site, and this plan; Claude Fable 5.1 and
  Claude Opus 5 are the two models tested and shown live on the site;
  an internal LLM council (`council-transcript-20260920T001404.md`)
  pressure-tested the track decision.
